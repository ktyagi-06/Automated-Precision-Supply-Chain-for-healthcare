# Automated Precision Supply Chain

An ML-powered supply-chain decision-support system: it forecasts product
demand, calculates statistically-grounded reorder points and safety stock,
flags stockout/overstock risk, and recommends exactly how many units to
order and from which supplier — surfaced on a live React dashboard.

This is a real, working project: synthetic-but-realistic data, an actual
trained-and-evaluated model (not a stub), a FastAPI backend, and a React
frontend, all wired together and tested end-to-end.

```
RAW DATA → CLEANING → FEATURE ENGINEERING → MODEL TRAINING (3 models compared)
→ MODEL EVALUATION → SAFETY STOCK / ROP CALC → REORDER RECOMMENDATION → REACT DASHBOARD
```

## 1. Regenerate data & retrain the model (optional — already generated)

```bash
cd data && python3 generate_data.py
cd ../ml && python3 train_model.py
```

This trains and compares **Linear Regression, Random Forest, and XGBoost**
on a proper time-based train/validation split (last 60 days held out — no
leakage), scores them on MAE / RMSE / MAPE, and saves whichever model wins
on validation MAE. On the current data, results were:

| Model             | MAE  | RMSE  | MAPE   |
|-------------------|------|-------|--------|
| Linear Regression | 7.51 | 10.37 | 19.87% |
| **Random Forest** | **7.22** | **9.79** | **19.75%** |
| XGBoost           | 7.29 | 9.88  | 19.10% |

Random Forest was selected (lowest validation MAE). Re-run `train_model.py`
any time new sales data lands in `sales_history.csv` to refresh the model.

## 2. Run the backend

```bash
python3 -m venv venv && source venv/bin/activate   # optional but recommended
pip install -r requirements.txt
cd backend
uvicorn main:app --reload --port 8000
```

Check it's alive: `curl http://localhost:8000/api/health`

Key endpoints:
- `GET /api/products` — product master data + current stock
- `GET /api/forecast/{product_id}?days=7` — ML demand forecast
- `GET /api/reorder/{product_id}?days=7` — full reorder recommendation
- `GET /api/reorder?days=7` — recommendations for every product
- `GET /api/alerts` — active stockout / overstock / demand-spike alerts
- `GET /api/suppliers` — supplier performance table
- `GET /api/dashboard-summary` — aggregated KPIs
- `GET /api/model-info` — model comparison + metadata
- Interactive API docs: `http://localhost:8000/docs`

## How the recommendation is calculated

For each product:

1. **Demand forecast** — the trained model predicts daily demand for the
   next N days, feeding each day's prediction back in as a lag feature for
   the next (iterative/recursive forecasting).
2. **Safety stock** — `z × σ(demand) × √(lead time)`, where `z` is the
   z-score for a 95% service level (1.645) and σ(demand) is the recent
   demand volatility for that product. This scales safety stock to how
   unpredictable each product actually is, rather than a flat buffer.
3. **Reorder point** — `(avg daily demand × lead time) + safety stock`.
4. **Recommended order qty** — `max(0, predicted demand over horizon + safety stock − current stock)`.
5. **Risk level** — CRITICAL / HIGH / WATCH / HEALTHY / OVERSTOCK, based on
   current stock vs. reorder point and projected days of stock remaining.

## Notes on the data

Since no real sales history was provided, `generate_data.py` synthesizes
two years of daily sales for 10 products with realistic trend, weekly and
yearly seasonality, promo spikes, and noise — so the model has real
patterns to learn rather than pure randomness. The current inventory
snapshot is deliberately varied (some products healthy, some low, some
critical, some overstocked) so the dashboard's alerts and statuses aren't
all the same on first load. Swap in real CSVs with the same schema and
everything downstream (training, API, dashboard) works unchanged.
